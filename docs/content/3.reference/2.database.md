The file opens in WAL mode. `article_id` is the primary key.

```sql
SELECT article_id, category, list_date_iso, heading, url
FROM articles
ORDER BY list_date_iso
LIMIT 5;
```

## articles

| Column | Content |
| --- | --- |
| `article_id` | 8 lowercase hex characters |
| `url` | Canonical article URL, without `opt` |
| `heading` | Text of `span.headline_avherald` |
| `list_date` | Date heading as printed |
| `list_date_iso` | `YYYY-MM-DD`, or empty when the heading did not parse |
| `icon` | File name of the category gif |
| `category` | `crash`, `accident`, `incident`, `news`, or `report` |
| `source_page` | List URL |
| `first_seen_at` | Set on insert, never overwritten |
| `last_seen_at` | Set on insert and on every later visit |

A repeat visit is one `INSERT ... ON CONFLICT` for the batch. The conflict update does not touch `first_seen_at`.

## crawl_state

One row per crawl key. The key is `{sort}|{categories}` or `url|{start_url}|{categories}`. `*` means every category.

`resume_url` is the next list page. `completed` means the previous run reached the end of that filter and the next run should stop when it meets a known id.

A page that is blocked or fails is not skipped. The bookmark keeps `resume_url` on that page, so the next run retries it instead of moving past it.

## Page log

The crawl also writes a JSON file, by default `<database stem>.pages.json` beside the database (`data/avherald.pages.json`). `--pages-log` or `pages_log` in `config.ini` moves it. `--dry-run` writes this file too, without touching SQLite or the bookmark.

```json
{
  "run_started_at": "2026-11-14T09:12:44+00:00",
  "pages": [
    {"url": "https://avherald.com/", "status": "ok", "attempts": 1, "error": null},
    {"url": "https://avherald.com/h?list=&opt=0&offset=...", "status": "blocked", "attempts": 2, "error": "avherald.com blocked this IP"}
  ],
  "resume_url": "https://avherald.com/h?list=&opt=0&offset=..."
}
```

| Field | Content |
| --- | --- |
| `run_started_at` | UTC ISO 8601 time the run began |
| `pages` | One entry per requested URL, in request order |
| `pages[].url` | The list URL that was requested |
| `pages[].status` | `ok`, `blocked`, or `failed` |
| `pages[].attempts` | Requests actually sent for that URL, including proxy retries |
| `pages[].error` | Short reason when status is not `ok`, otherwise `null` |
| `resume_url` | Page the next run opens, or `null` when there is nothing left |

A proxy switch does not create a second entry: the retry is part of the same page, and `attempts` grows. `ok` means the page came back, `blocked` means every configured proxy served the ban page, and `failed` means an HTTP or network error survived the last proxy. After a `blocked` or `failed` page no further pages are requested.

The file is replaced into place only after the whole JSON document has been built, so a run that ends normally always leaves a parseable file. A write error fails the run with exit status `1`.

## Which rows are kept

A listing row is kept only when it has `span.headline_avherald` and one of `crash.gif`, `accident.gif`, `incident.gif`, `news.gif`, `report.gif`. Nested table wrappers, footer links, and interview links are skipped. The id must match `^[0-9a-f]{8}$`.
