# ETF异动雷达：规则与数据

构建时设置`ENABLE_RADAR=1`启用。雷达与已有图表共用数据快照和共享缓存；云端测试与正式发布均保留该开关，避免日度更新覆盖雷达。

## 展示与规则

| 模块 | 数据与判断 |
|---|---|
| 累计成交倍数 | 当前20只核心ETF自开盘至观察时点的完整分钟成交额，分别除以最近20日和60个完整交易日同进度均值；同时展示两套倍数与样本数 |
| 短时成交倍数 | 当前5分钟成交额分别除以20／60日历史同窗均值；不跨午休，至少5亿元，两套基准连续两个逐分钟窗口均达到2倍才确认 |
| 累计放量观察 | 默认1.5倍；仅20日触发提示「近期放量」，仅60日触发提示「长周期偏高」，两者触发提示「持续关注」；开盘前15个交易分钟先观察，各基准必须满20／60个完整样本，分母为零不判断 |
| 单只日度资金信号 | 最新已确认日度净申购估算绝对值达到10亿元；正负方向分别标注，明确归属日期 |
| 时点回放 | 使用本日已缓存分钟数据，截止所选时点重算；基金卡片始终显示独立标注的最新行情与日度资金日期 |

阈值为可调整的成交观察规则，已通过历史缓存回放比较触发频率；方法与统计结果见下文。两套基准统一使用可调的累计阈值（默认1.5倍），取消单一20日达到2倍就升级确认的规则。60日不足时仍可展示20日观察，不降级冒充60日样本，也不作双基准确认。20日包含在60日中，双基准作为一组相关的筛选条件使用。顶部导航与侧边目录均提供「ETF异动雷达」入口，并随滚动高亮当前栏目。模块分别展示成交活跃度和已确认日度申赎。日度净申赎按既有沪深份额对齐和原始净值公式计算，不从成交额或涨跌幅推导。

单只ETF卡片提供价格、涨跌、成交额与日度净申购。未保存单只ETF历史分钟基准，因此本版不生成单只ETF盘中成交倍数。整体分钟比较使用已有20只篮子的历史快照。

## 数据与隔离

当前行情来自20只核心ETF的共享缓存，历史基准来自快照内完整分钟样本。后台采集器把计算过程中已有的逐基金结果保存为`core_fund_daily`，随日度归档发布，合计与核心篮子核对，不增加查询次数。

网页交互只重算缓存数据，不调用FtShare、不产生采集请求。仍使用只读缓存网关和关闭的访客采集接口。网页构建与发布不修改采集时刻和DNS；生产运行参数由部署者管理。

## 离线窗口回放

运行 `node scripts/radar-window-review.mjs <seed.json> <report.md>`，仅读取本地分钟快照，不调用FtShare。观察10:00、11:00、14:00、15:00四个固定时点，每个观察日仅用此前历史。

本次206个完整快照（2026-01-05—2026-11-11），共同可比146日。收盘1.5倍阈值：20日触发12日、60日13日、双基准10日；不能据此断言60日更少触发或双基准预测更准。详见 [窗口回放报告](radar-window-review.md)。

## 正式发布检查

发布前验证最新归属日的20只逐基金净申赎齐全、合计与已有篮子一致、至少60个完整历史分钟快照。先在测试项目发布验证，正式项目复用同一归档和固定源码；发布后再验证雷达开关、双基准资源与逐基金数据。失败保留／恢复上一正式部署。
