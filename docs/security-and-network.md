# 网络与主机配置

Mac mini通过同机Caddy提供HTTPS，Node服务监听`127.0.0.1:8080`。域名示例为`etf.example.com`。

## 检查部署主机

```sh
npm run mac:check
```

报告保存到`.local/macmini-check.json`，包含网卡与出口地址、代理启用状态、端口、防火墙、凭据文件权限及服务状态。它执行只读检查，报告供部署者核对。

## 验证HTTPS入口

配置域名、证书和路由后，从外部网络验证目标主机：

```sh
curl --noproxy '*' --connect-timeout 5 --max-time 15 \
  --resolve etf.example.com:443:YOUR_PUBLIC_IPV4 \
  https://etf.example.com/api/health
```

核对证书与返回的构建信息，再通过手机移动网络访问完整页面，检查图表、雷达及数据时间。IPv4和IPv6分别验证；出口地址、NAT及入站路由一并检查。验证通过后配置公共DNS。

## 服务配置

| 项目 | 配置 |
|---|---|
| 网页进程 | 普通专用用户、独立目录、回环监听 |
| 公网入口 | HTTPS代理接收443；80按跳转与证书验证需要配置 |
| 读取接口 | GET／HEAD，按固定路由读取已发布数据 |
| 请求管理 | Node默认单IP每分钟180次API请求、总并发32 |
| 行情来源 | 后台统一采集；网页读取文件缓存或共享KV |
| 代理信任 | 显式信任同机代理的客户端地址转发 |
| 凭据与证书 | 后台Secret或权限600的受限文件 |
| 历史恢复 | 保存快照与代码版本，更新前验证，失败恢复前一版本 |

根据实际访问量管理托管平台资源，并按所有采集进程合计的数据额度设置采集频率。网页进程与采集器分别管理权限和运行环境。

保持系统、Node与代理软件更新；监控缓存时间、采集失败、磁盘和证书有效期。Mac登录任务在用户登录后运行，主机保持供电、联网与唤醒。
